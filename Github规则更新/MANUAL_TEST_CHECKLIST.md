# Github规则更新 Intent 真机验收清单

## 准备

- [ ] 在主界面配置 GitHub owner、repo、branch 与有效 token。
- [ ] 在设置页按“每行一个”配置至少两个策略，保存后重新进入设置确认仍存在。
- [ ] 验证空行和完全重复策略会被忽略，含逗号的策略会阻止保存并显示错误。
- [ ] 在主界面打开一个小于 1 MB 的目标规则文件，确认文件可正常读取。
- [ ] 准备一个含文件头注释、空行和至少两条规则的测试文件。

## 分享页面

- [ ] 在 Safari、备忘录等 App 选中 `gateway.icloud.com:443`，分享至 Scripting，并能看到“Github规则更新”。
- [ ] 页面显示可编辑的分享文字、规则样式候选与“添加到线上规则”按钮。
- [ ] 页面显示策略选择项，首次默认选中预置列表第一项。
- [ ] 页面不显示“创建新规则/添加到规则集”切换，也不显示“规则集”选择行。
- [ ] 默认选中 `DOMAIN,gateway.icloud.com`，并依次显示完整域名、`icloud.com`、`com` 的 `DOMAIN-SUFFIX` 候选。
- [ ] 修改输入为 URL、IPv4、括号 IPv6 后，候选实时更新；无效文字显示错误状态。
- [ ] 在深色模式、小屏设备和较大动态字体下，输入、候选和底部按钮仍可操作。

## 目标与提交

- [ ] 未配置或未打开过文件时，按钮禁用并提示先在主界面完成准备。
- [ ] 点击添加会先读取远端最新文件；已有同类型同值规则时阻止重复提交并显示位置。
- [ ] 确认页显示仓库、分支、路径、完整规则和“规则区第一行”。
- [ ] 普通域名规则格式为 `DOMAIN,值,策略,extended-matching`；`DOMAIN-SUFFIX` 使用相同参数顺序。
- [ ] 四种内置拒绝策略 `REJECT`、`REJECT-DROP`、`REJECT-NO-DROP`、`REJECT-TINYGIF` 的域名规则格式为 `DOMAIN,值,策略,pre-matching,extended-matching`。
- [ ] 普通 IP 规则格式为 `IP-CIDR,值,策略,no-resolve`；内置拒绝策略格式为 `IP-CIDR,值,策略,pre-matching,no-resolve`，且不包含 `extended-matching`；IPv6 使用相同参数顺序。
- [ ] 成功提交后再次打开 Intent，默认选中上次成功使用的策略；删除该策略后回退到第一项。
- [ ] 确认后 GitHub 提交信息为 `Add <规则> via share`。
- [ ] Intent 提交成功后，文件头保持不变，新规则位于规则区索引 0，在原有前置注释和空行之前。
- [ ] 制造远端并发修改后，409 不覆盖远端内容，并提示返回重新获取。
- [ ] 401、403、404、断网和超时均显示可理解错误，输入与候选不会丢失。
- [ ] 成功页点击“完成”、编辑页点击关闭、下拉关闭页面时，Intent 均正常退出。

## 主界面回归

- [ ] “+ 新增规则”和“+ 新增注释”在同一个圆角分组内上下排列，按钮间距与筛选区域一致。
- [ ] 点击“+ 新增注释”后输入框默认为 `#`；空内容保存为 `#`，未输入前缀时自动补成 `# 内容`，中文与 Emoji 正常显示。
- [ ] 输入换行时阻止保存并提示仅支持单行；取消不会产生未保存变更。
- [ ] 新注释位于第一条实际规则之前；如果顶部已有新增规则，之后添加注释会把注释移动到该规则之前。
- [ ] 重新打开文件后，前置注释区块仍显示且可点击编辑；文件头元数据继续隐藏并原样保留。
- [ ] 修改或删除已有独立注释会启用保存，并在 Diff 中显示正确的原始值和新值；左滑删除同样生效。
- [ ] Intent 新增首条规则后，顺序为“文件头 → 新规则 → 原有前置注释/空行 → 原有规则”。
- [ ] 仓库浏览、目录切换、文件打开、编辑、手动新增、删除、排序、Diff 与提交正常。
- [ ] 主界面连续新增规则时，后新增规则位于规则区最前面；原有内容的相对顺序不变。
